Microsoft's monthly patch release landed with a record-setting number of fixes, GitLab is dealing with active exploitation of a critical flaw, and researchers have detailed a new exploit chain linking browser bugs to Windows kernel access. Microsoft's September Patch Tuesday release addressed nine hundred seventy four vulnerabilities, according to the Check Point Research Threat Intelligence Report published today. Two of those flaws are already being exploited in the wild. The first, tracked as CVE-2026-81963, sits in the Windows Update Stack and allows privilege escalation. The second, CVE-2026-85880, affects the Advanced Local Procedure Call component and also allows elevation of privilege. Per Check Point, both let a low-privileged local attacker climb to full SYSTEM-level access, meaning someone who already has a small foothold on a machine can turn that into complete administrative control. That distinction matters because it's the difference between a nuisance bug and a tool that turns a minor breach into a total takeover. This wave of patching arrives alongside a separate and already-exploited flaw in GitLab, according to Cybersecurity Dive, which further widens the attack surface security teams have to manage this week, spanning both the operating systems that power endpoints and the infrastructure tools developers rely on daily.

Separately, GitLab is facing active exploitation of a critical path traversal vulnerability tracked as CVE-2026-85706, according to Cybersecurity Dive and the Cybersecurity and Infrastructure Security Agency. The flaw affects both the Community and Enterprise editions of GitLab and allows an unauthenticated attacker to read arbitrary files through the platform's repository commits application programming interface, without needing to log in at all. GitLab shipped a patch on September tenth, but CISA added the flaw to its Known Exploited Vulnerabilities catalog just today, September fourteenth, after confirming malicious actors had already begun exploiting it. Per the Senserva CVE tracker, the flaw carries a maximum severity score of ten out of ten across all affected versions, from eighteen point seven through nineteen point three point one. CISA is requiring federal agencies to mitigate the issue by Monday. The broader concern, as Cybersecurity Dive notes, is supply chain exposure. GitLab underpins the code repositories and continuous integration pipelines for a huge share of software development teams, so a flaw that lets outsiders quietly read internal files has implications well beyond any single organization.

That exploitation wave isn't limited to Microsoft and GitLab. According to the Senserva Trustworthy AI CVE Ranking, CVE Brief, and Check Point Research, security teams are now tracking confirmed exploitation across a wide range of other products. Two Chromium bugs, a type confusion flaw and a related out of bounds write issue, are being used in active attacks. Multiple critical flaws in MikroTik RouterOS and Citrix NetScaler have also been confirmed exploited, alongside an authentication bypass in JFrog Artifactory that attackers are using to plant backdoors. A flaw in ConnectWise ScreenConnect allows file upload and execution without authorization, and firmware vulnerabilities in D-Link and Totolink routers, carrying severity scores between nine point eight and nine point nine, are now dominating attacks against network hardware. Taken together, these reports point to something beyond a handful of isolated bugs. Attackers appear to be working simultaneously across governance tools, development pipelines, networking equipment, and remote access software, which raises particular concern for organizations running distributed infrastructure or branch offices, where that mix of systems is common and patching can lag.

Security researchers also detailed a new exploit chain, nicknamed BlueMoon, that links a Chromium browser flaw to a Windows kernel escalation, according to the Check Point Research Threat Intelligence Report. The chain uses the same V8 JavaScript type confusion bug mentioned earlier, combined with a Windows privilege escalation flaw, to let an attacker break out of the browser's security sandbox entirely and reach kernel-level access on the underlying machine. Per Check Point, espionage-focused groups have deployed this chain against targets even after Chrome's patches became available, exploiting the gap in time before those patches actually reach every vulnerable browser installation. The practical effect is that a person only needs to visit a malicious webpage to end up with a fully compromised Windows machine, and the risk extends to any browser built on the Chromium engine, not just Chrome itself.

Now, a closer look at today's lead story, Microsoft's September Patch Tuesday and what a release of this size actually means for the people responsible for keeping systems secure.

Nine hundred seventy four vulnerabilities in a single month's release is an unusually large number, even by the standards of a company that ships fixes on a fixed monthly schedule specifically so that IT departments can plan around it. Patch Tuesday exists as a predictable rhythm, giving system administrators a known window each month to test and deploy updates rather than reacting to a constant, unpredictable drip of fixes. A release this large stresses that entire process. Security teams don't just apply patches automatically in most organizations. They have to triage which vulnerabilities pose the greatest risk, test that patches don't break existing systems, and roll updates out in stages across servers, workstations, and specialized equipment that may not tolerate downtime easily.

The two actively exploited flaws in this release deserve particular attention because of what they target. The Windows Update Stack vulnerability and the Advanced Local Procedure Call flaw both live deep in core parts of the operating system that most users never interact with directly, but that carry broad privileges by design. According to Check Point Research, both flaws share the same basic mechanism, letting an attacker who already has limited access to a machine escalate that access to full SYSTEM-level control. This two-step pattern, gaining a small foothold first and then escalating privileges second, is one of the most common paths attackers use to move from a minor compromise to complete control of a machine. It's precisely why these particular flaws are already being used in real attacks rather than sitting as theoretical risks. An attacker doesn't need to breach Windows from the outside first. They need only some initial access, however minor, and these bugs supply the rest.

Context matters here too. This Patch Tuesday didn't arrive in isolation. It landed the same week CISA confirmed active exploitation of the GitLab flaw, and the same week researchers detailed the BlueMoon browser-to-kernel exploit chain. None of these are connected campaigns as far as current reporting shows, but together they illustrate a broader pattern security teams are grappling with heading into the fall. Attackers are working across every layer of the technology stack at once, from the browser someone uses to check email, to the operating system underneath it, to the development tools engineering teams use to build software, to the network hardware that connects it all. For an individual organization, the practical challenge isn't any single patch. It's the sheer volume of urgent, simultaneous fixes competing for the same limited pool of security staff and the same maintenance windows. Vulnerability management teams are now weighing not just severity scores but which flaws have confirmed exploitation, since that's often the deciding factor in what gets patched first when everything can't be patched at once.

For everyday users, the practical takeaway from all of this is straightforward, even if the underlying detail is technical. Windows updates should be installed as soon as they're available rather than deferred, GitLab administrators should confirm they're running a patched version above nineteen point three point one, and anyone using a Chromium-based browser should make sure automatic updates are actually turned on, since the BlueMoon exploit chain specifically takes advantage of the lag between a patch's release and its installation on individual machines.
